# 第三问模型（修正版）

## 1. 定位与信息边界

采用每6小时重求解的因果滚动样本平均近似（SAA/MPC），不宣称严格多阶段随机最优（`strict_multistage_optimal=false`）。每天0:00制定计划，6:00、12:00、18:00仅调整未交付区间。所有预测和残差样本均受发布日期截断；实际值仅在对应时段结束后进入后续决策。

区间采用起点口径。自然日为00:00—24:00（144个10分钟区间）；模板行为00:10—次日00:00（144个10分钟区间），模板末列“次日00:00”等于下一自然日的00:00区间。自然日实际量跨行映射：当日的00:00取自上一原始行末列，禁止同一行循环移位。自然日费用单独按00:00—24:00统计，模板行费用单独按本行144列统计，两者相差恰好一个午夜边界列，不能跨表相加。00:00合同量锁定为前一日最后一次提交的次日00:00量，此项为合同假设。

## 2. 净负荷情景

附件3整点光伏预报以发布时刻前最近一个已观测10分钟值为锚点，分段线性插值到10分钟。负荷中心预测由最近同星期轮廓与最近7日轮廓的稳健中位数加权得到，权重按历史28日MAE选择。

对每个发布时刻分别构造历史残差轮廓，滚动选择7日或14日窗口，形成等权净负荷情景。0:00最晚使用前两日的完整残差；日内发布最晚使用前一日完整残差。残差轮廓与中心预测使用同一权重，即残差必须来自同一个负荷预测器，否则情景分布不能代表实际预测误差。

## 3. 共同储能轨迹

同一发布时刻的全部情景共享购电合同量、充电量、放电量和SOC轨迹，只有紧急购电与弃电允许按情景变化：

\[
A_h+D_h+E_h^\omega-C_h-U_h^\omega=N_h^\omega,
\]

\[
S_{h+1}=S_h+0.9C_h-D_h/0.9.
\]

发布向量的最后一个区间（次日00:00—00:10）的储能动作不提交，约束为 \(C=D=0\)；该区间的储能由次日0:00模型决定，购电量仍由本日0:00计划及其后续调整确定。终端储能价值施加于24:00时刻的SOC \(S_{H-1}\)，与回测结转的SOC为同一状态。

下一发布时刻前的36个10分钟储能动作严格按该共同轨迹执行，不再用事后贪心规则覆盖。实际情景下的紧急购电和弃电由能量缺口直接确定：

\[
\Delta_t=N_t^{act}-(A_t+D_t-C_t),\qquad E_t=(\Delta_t)^+,\qquad U_t=(-\Delta_t)^+.
\]

因此实际结果中允许出现“紧急购电同时充电”。它不是执行器自相矛盾，而是发布时已锁定的共同储能轨迹在实际净负荷偏高时仍被执行、缺口由紧急购电补足的结果。求解器给出并保存该轨迹，回测不重新调用贪心补救，报告中按审计结果如实统计并解释。

## 4. 结算口径

主口径为保守解释：初始计划费用保留；每次提交相对当前生效合同逐笔计费。若本次上调、下调量为 \(Q_h^+,Q_h^-\)，则本次新增费用为

\[
1.5p_hQ_h^++0.5p_hQ_h^-.
\]

每次修改均保存，取消后恢复也会产生两次费用。该合同解释为“需人工确认”。

主口径下下调恒被占优，最优解取 \(Q^-\equiv0\)：减少已支付电量既要再付 0.5p，又会抬高按 5p 计价的紧急购电缺口，而收益为零。因此主策略的固定电量按退款口径重算的结算值与原口径严格相等（见 `docs/q3_derivation.md` 第 4.1 节），二者相同是恒等式而非重复计算。允许退款的敏感性口径重新优化后可以自由下调，费用明显更低，仍作为独立对照。

另计算退款且仅按最终净额结算的敏感性口径：

\[
p_hA_h^{final}+0.5p_h|A_h^{final}-G_h|.
\]

该口径单独重新优化，并在主策略固定电量上再结算一次；两者都只作敏感性，不与主口径混算。

## 5. 策略比较

独立回测日内新预报集合 \(\varnothing,\{6\},\{12\},\{18\},\{6,12\},\{6,18\},\{12,18\},\{6,12,18\}\)，每套策略保持自己的SOC、跨日计划量和跨日最终合同量。另设“仍在6/12/18重优化但冻结0:00光伏预报”的基线，以分离新预报信息和单纯重优化机会。

零点计划没有建立完整情景树来联合定价未来调整机会，这是剩余的模型近似。

## 6. 审计与断点续跑

- `release_logs/<策略>.json` 保存每次发布的完整合同向量、共同充放电向量、信息截止时刻、残差窗口、情景数、求解状态和逐次调整费用；`release_log.json` 为主策略的发布日志。
- `checkpoints/<策略>.json` 保存该策略逐日结果与发布日志，并记录输入SHA256、模型版本与参数签名。签名完全一致时才复用，支持中断后续跑；签名不一致或缺失时重新计算。
- 发布时的共同充放电轨迹与回测实际执行量逐时段核对，用于证明执行端未覆盖优化结果。
