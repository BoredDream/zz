## A3. 第三问模型代码复核

### 目标

确认修正版代码在大规模运行前不存在变量索引和费用映射错误。

### 核心模型要求

同一发布时刻的所有情景必须共享：

- 计划或调整购电量；
- 充电量；
- 放电量；
- SOC轨迹。

仅以下变量允许随情景变化：

- 紧急购电量；
- 弃电量。

### 必查公式

能量平衡：

\[
A_h+D_h+E_h^\omega-C_h-U_h^\omega=N_h^\omega.
\]

SOC递推：

\[
S_{h+1}=S_h+0.9C_h-D_h/0.9.
\]

物理边界：

\[
1200\le S_h\le10800,
\qquad 0\le C_h,D_h\le833.3333.
\]

主口径第 \(k\) 次调整：

\[
A_h^k-Q_{h,k}^{+}+Q_{h,k}^{-}=A_h^{k-1}.
\]

调整新增费用：

\[
1.5p_hQ_{h,k}^{+}+0.5p_hQ_{h,k}^{-}.
\]

### 必查时间映射

- 自然日数组：00:00、00:10、……、23:50；
- 原始附件行：00:10、……、23:50、次日00:00；
- 自然日00:00必须取上一原始行末列；
- 模板一行必须覆盖00:10至次日00:00；
- 禁止同一行循环移位；
- 自然日调整费用与模板行调整费用必须分别映射；
- 模板行末列的次日00:00调整费用不得遗漏。

### 小规模测试

- [ ] `py_compile`通过；
- [ ] 单日、单情景测试通过；
- [ ] 多情景当前储能动作完全相同；
- [ ] 两个未来不同但当前观测相同的情景不能选择不同当前动作；
- [ ] 计划、调整和执行使用同一SOC定义；
- [ ] 实际执行不再调用贪心规则覆盖优化结果。

### 预计时间

15—25分钟。

# 最终状态定义

只有同时满足以下条件，项目才可标记为“完成”：

1. 四问模型均有明确数学表达和信息边界；
2. 所有要求的Excel结果文件由真实数据生成；
3. 每个结果均能由明细独立复算；
4. 物理约束、时间映射和费用口径全部验收；
5. 论文数字、表格、图形和工作簿完全一致；
6. 最终PDF已逐页检查；
7. 所有不确定合同假设均明确标注“需人工确认”；
8. 不存在把旧结果、部分运行或未验证结果冒充最终结论的情况。
